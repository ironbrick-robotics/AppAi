COMPETITIVE ROBOTICS PROMPT CLASSIFICATION RUBRIC

Classify each student interaction into exactly one level from L1 to L5.


L1 — GENERAL / CONCEPTUAL

The student asks a broad or general question without specifying technical parameters or algorithmic details.

Examples:
- Τι είναι το Mini Sumo;
- Πώς λειτουργεί ένα line follower;
- Τι κάνει ο αισθητήρας αντιπάλου;


L2 — BASIC FUNCTIONAL REQUEST

The student requests one basic robot action or function without providing detailed parameters or combining multiple conditions.

Examples:
- Θέλω το robot να κινηθεί μπροστά.
- Κάνε το robot να ψάχνει τον αντίπαλο.
- Πώς μπορώ να σταματήσω τα μοτέρ;


L3 — PARAMETERIZED / TECHNICAL REQUEST

The student provides specific parameters, values, speeds, times, sensor conditions or other technical constraints.

Examples:
- Θέλω τα μοτέρ να λειτουργούν στο 70%.
- Αν η τιμή του αισθητήρα είναι μικρότερη από 300, να σταματά.
- Θέλω να περιστρέφεται για 500 ms.


L4 — ALGORITHMIC / MULTI-CONDITION LOGIC

The student combines sensors, actions, conditions, states or strategy.

Typical expressions include:
- if
- when
- else
- then
- while
- otherwise

Examples:
- Αν δει αντίπαλο να επιτεθεί, αλλιώς να περιστρέφεται.
- Αν δει τη γραμμή να κάνει πίσω και μετά να συνεχίζει την αναζήτηση.
- Όταν ο αριστερός αισθητήρας βλέπει γραμμή, διόρθωσε την πορεία.


L5 — DEBUGGING / ANALYSIS / METACOGNITION

The student asks for error correction, explanation, debugging, reasoning or evaluation of an existing solution.

Examples:
- Γιατί βγαίνει έξω από το dohyo;
- Γιατί δεν βλέπει τον αντίπαλο;
- Τι λάθος έχει ο κώδικάς μου;
- Γιατί ταλαντώνεται το line follower;
- Πώς μπορώ να βελτιώσω αυτή τη στρατηγική;

L5 includes syntax errors, logical errors, debugging, explanation of unexpected behavior and questions requiring reflection on an existing solution.

INTERPRETATION AND RESEARCH USE

The L1-L5 label describes the cognitive/technical character of the
CURRENT interaction. It is not a permanent student level and must not
be interpreted as a ranking of the student's overall ability.

The levels are categories of interaction complexity/type, not grades.

A student may naturally produce interactions from different levels
during the same activity.

When an interaction contains characteristics of more than one level,
classify according to the dominant purpose of the student's request.

Use the following precedence when the dominant purpose is clear:

- If the student is primarily asking to diagnose, explain, correct,
  evaluate or improve an existing behavior/solution, classify L5,
  even when parameters or multiple conditions are also mentioned.

- Otherwise, if the request primarily combines multiple conditions,
  states, sensor-action relationships or strategy logic, classify L4.

- Otherwise, if the request primarily specifies technical parameters,
  values, times, speeds or explicit sensor conditions, classify L3.

- Otherwise, if the request asks for one basic robot action/function,
  classify L2.

- Otherwise, use L1 for broad conceptual/general questions.

Do not infer a student's intelligence, competence or achievement from
a single L1-L5 classification.
